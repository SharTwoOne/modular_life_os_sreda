# Модульная Life OS среда

Скилл, который разворачивает человеку **базовую версию Life OS** на его компьютере: систему сбора
контекста, из которой потом вырастает своя Life OS. Устроена так же, как Life OS автора: среда
собрана из модулей, у каждого свой файл правил, своя карта и своя машинная карта.

Работает в Claude Code. Можно пройти в паре с архитектором (на созвоне) или одному.
Файлы и папки называются по-английски, текст внутри — на языке человека.

---

## Как это идёт

1. Агент говорит: «Сейчас мы соберём твою базовую версию: систему сбора контекста, которая поможет
   тебе в будущем собрать свою Life OS», и задаёт вопросы.
2. Распаковка «обо мне»: кто ты, проекты, цели, как с тобой говорить, рутина, границы, ценности.
3. Агент создаёт папку на компьютере и раскладывает ответы по модулям, только словами человека.
4. Собираются машинные карты `architecture.json`: общая и по одной на каждый модуль.
5. Агент предлагает собрать визуальный стиль в HTML: человек присылает свою дизайн-систему или
   референсы, агент собирает модуль `brand/` под его стиль.

## Что получится у человека

```
~/anna-os/                     ← папка среды, имя латиницей
├── CLAUDE.md                  ← главный файл: правила, таблица модулей, маршрутизация
├── map.md                     ← карта для человека: что где лежит
├── architecture.json          ← машинная карта: дерево, метки, документы, список модулей
├── architecture.py            ← пересобирает все карты. Его же зовёт хук после каждой правки
├── data-standard.md           ← как называть файлы, что ставить в шапку
├── intervention-rule.md       ← что агент делает сам, когда зовёт, что всегда делает человек
├── gates.md                   ← проверки «да/нет» перед сдачей работы + личный стоп-лист
├── automations.md             ← что отнимает время и что из этого отдаём агенту
├── about-me/                  ← модуль: профиль, как говорить, цели, дословная речь
├── constitution/              ← модуль: фундамент, принципы, проекты. Пишет сам человек
├── memory/                    ← модуль: что агент узнал в работе
├── brand/                     ← модуль: визуальный стиль. Появляется, когда прислал референсы
│   ├── style-reference.md     ← истина: цвет, шрифты, формы, компоненты
│   └── style-reference.html   ← витрина стиля, красится в его токены
└── <project>/                 ← модуль на каждый проект
```

**Модуль** — папка верхнего уровня, которую можно открыть отдельно и работать только в ней.
У каждого внутри три вещи:

| Что | Файл | Для кого |
|---|---|---|
| Правила модуля | `CLAUDE.md` | для агента: что читать первым, что можно, чего нельзя |
| Карта раздела | `00-overview.md` | для человека: что где лежит |
| Машинная карта | `architecture.json` | для поиска: дерево, метки, документы, правила модуля |

Машинные карты руками не правятся. `architecture.py` берёт назначение папок из таблиц `map.md`
и `00-overview.md`, а «что читать сначала» и правила — из модульных `CLAUDE.md`.

## Как запустить

**Вариант 1. Разово, из этой папки.**

```bash
git clone https://github.com/SharTwoOne/modular_life_os_sreda.git
```

```bash
cd modular_life_os_sreda && claude
```

Дальше написать агенту «начни». Он спросит, где создать среду, и поведёт по шагам.

**Вариант 2. Поставить скилл насовсем.** После этого он доступен в любой папке командой `/modular-life-os-sreda`.

```bash
cp -r modular_life_os_sreda/.claude/skills/modular-life-os-sreda ~/.claude/skills/
```

## Три режима

| Режим | Когда | Как идёт |
|---|---|---|
| **Архитектор на созвоне** | Настраиваешь среду другому человеку | Агент подсказывает архитектору следующий вопрос, архитектор спрашивает голосом и вставляет ответы |
| **Расшифровка** | Созвон уже был и записан | Вставляешь расшифровку, агент раскладывает её по файлам и собирает список того, что не прозвучало |
| **Сам** | Человек проходит один | Агент задаёт по одному вопросу и ждёт ответа |

## Что внутри репозитория

| Путь | Что это |
|---|---|
| `.claude/skills/modular-life-os-sreda/SKILL.md` | Сам скилл: порядок работы от первого вопроса до проверки среды |
| `…/references/interview.md` | Вопросы по семи блокам и куда ложится каждый ответ |
| `…/references/environment-rules.md` | Все правила организации среды и зачем каждое. Для архитектора |
| `…/references/automations.md` | Каталог автоматизаций: как узнать по словам человека и с чего начать |
| `…/templates/` | Шаблоны файлов среды, которые скилл раскладывает и заполняет |
| `…/templates/architecture.py` | Сборщик машинных карт: корневой и по одной на модуль |
| `…/templates/.claude/settings.json` | Хук: пересобирает карты после каждой правки файла |
| `…/brand-template/` | Шаблон модуля `brand/`: правила, канон стиля в MD и витрина в HTML |
| `…/references/visual-style.md` | Как собрать визуальный стиль из дизайн-системы или референсов |
| `…/scripts/check.py` | Гейты самой среды: всё ли на месте, нет ли пустых обязательных мест и секретов |
| `…/scripts/connect-memory.py` | Подключает `memory/` к памяти Claude Code, чтобы она читалась в каждой сессии |

## Главные принципы

1. **Только слова человека.** Агент не додумывает ни цифр, ни целей, ни формулировок. Пустое место честнее выдуманного.
2. **Файлы, а не чат.** Всё важное лежит MD-файлами у человека на компьютере и переживёт смену модели и подписки.
3. **Один вход.** Агент всегда начинает с `CLAUDE.md` и `map.md` и не теряется в папках.
4. **Правило и гейт, а не надежда.** Что агенту можно без спроса, записано заранее. Перед сдачей работа проходит проверки «да/нет».

Подробно: [environment-rules.md](.claude/skills/modular-life-os-sreda/references/environment-rules.md).
